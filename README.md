# InkEcho

[![CI](https://github.com/Silent-Rain02/inkecho/actions/workflows/ci.yml/badge.svg)](https://github.com/Silent-Rain02/inkecho/actions/workflows/ci.yml)

InkEcho 是一个面向任意小说的续写与内容问答工作台，默认附带《蛊真人》作为示例知识空间。

接手开发可先阅读 [HANDOFF.md](HANDOFF.md)。

## 项目简介

项目围绕本地小说知识空间，提供原作内容问答、角色 / 世界观检索和非照抄式剧情续写空间；首次启动时可直接使用默认的《蛊真人》示例，也可以上传并切换到自己的小说。

## 当前状态

当前已完成一个可本地运行的小说知识空间工作台，支持多种模型服务、流式对话、原作检索、项目管理、JSON 备份和多小说切换。上传文件会在本机后台解析，原始小说文件不会提交到 GitHub。

## 原作记忆算法

InkEcho 已在本仓库内实现小说专用的关联记忆层，不依赖外部记忆服务。它只接收通过证据校验和独立审查的原作事实，并构建实体记忆痕迹、共现关系和多信号检索索引；问答可进行两跳关联召回，续写可按章节截止点阻断未来信息，同时每条结果都保留章节与逐字原文依据。

新索引默认处于隔离试验状态。只有使用准确记忆版本完成推广后，产品问答才会优先使用；索引缺失、未推广或原文版本变化时会自动回退到现有原文检索。设计细节见 [ECPHORY_MEMORY_ARCHITECTURE.md](ECPHORY_MEMORY_ARCHITECTURE.md)。

任意上传小说都可以在“空间记忆 → 原作知识”中显式启动深度记忆：系统默认从全书均匀选择 6 个代表章节，在后台逐章抽取并独立核对。中断时保留已完成进度，质量未通过时不会写入问答；通过后先生成待启用版本，用户确认后才切换为正式记忆。原文问答不需要等待这一步，且原文更新会自动停用旧记忆。使用远端模型前，页面会明确说明代表章节的发送范围；Ollama 可留在本机完成。

默认《蛊真人》空间当前已启用经跨卷抽取、当前规则预检、整库二审和修复复核的正式记忆版本：覆盖 20 个样本章、97 条事实和 147 个实体痕迹，24 道固定召回题与 3 道真实模型问答均通过。直接事实题会使用最窄充分证据，未覆盖问题继续回退全文检索；这不等同于宣称全书所有章节都已模型化。

会随剧情推进变化的知识不会被压成一个“最终值”。同一人物关系、势力归属、持有物或排名可以按不同章节保留多条带原文依据的事实；续写会使用当前章节截止点排除未来事实，问答则结合用户指定的早期、后期或具体章节选择对应证据。例如奇蛊排名发生变化时，早期结论与后期结论都可以保留，而不是用后期数字覆盖前文设定。尚未覆盖到对应章节时，系统继续回退原文检索并明确依据不足。

## 已实现

- 作品名称、时代氛围和世界观备注
- 小说库主入口：每本小说拥有独立的原作索引、空间笔记和创作项目；切换小说时检索与长期记忆自动隔离
- 任意小说的深度记忆后台任务：代表章节采样、逐字证据校验、独立模型审查、断点续建、质量失败重跑、不可变 pilot 与显式启用均已接入产品
- 小说库入口会直接提供“开始续写 / 内容问答 / 查看资料”三条路径；解析未完成的空间会明确禁用内容问答，避免用户走到发送时才发现原文不可用
- 首屏交互按“高频任务优先”重排：当前小说已就绪时，工作区引导直接提供“内容问答 / 开始续写”两个任务入口；原作资料、空间记忆、故事管理和模型设置收进带有明确说明的“更多工具”，降低首次使用的选择压力
- 当前小说引导栏进一步收敛为三个可理解的任务：“内容问答”“开始续写”“查找原作”；空间状态和小说空间管理默认折叠，避免用户先理解解析、记忆、项目等内部概念
- 顶部“功能菜单”会按“续写 / 问答 / 原作 / 记忆 / 场景与角色 / 模型服务”提供可搜索的任务入口，不要求用户记住页面名称；仍保留 ⌘ / Ctrl + K 快捷打开
- 前端展示采用全新的“左侧当前小说导航 + 右侧任务主区”结构：左侧固定显示当前小说和高频任务，右侧只承载当前页面内容；原作资料、空间记忆、故事管理和模型服务作为二级工具展开，不再使用原先的横向工作区堆叠布局
- 工作台以“会话历史侧栏 + 当前对话”组织任务：切换续写、内容问答、改写或角色独白时会自动保存当前会话并开启独立会话，避免不同任务共享对话上下文；历史会话可以随时切回
- 同一本小说有多个创作项目时，小说卡片会显示项目数量，点击续写优先恢复当前项目，否则打开最近更新的项目，不会默认跳回最早分支
- 已上传小说空间支持重命名；重命名只更新空间显示名称，不改动原文、内部文件名、章节索引、空间记忆或项目绑定
- 小说库支持将 TXT、Markdown、HTML、DOCX、EPUB、FB2 或 PDF 直接拖入上传入口；所有格式都会先按原始字节上传，再由服务端按文件后缀解析和识别编码，避免中文文本在 JSON 请求体中额外膨胀，也避免文档结构被浏览器文本解码破坏；拖拽上传与点击选择共用异步解析、失败重试和空间绑定流程
- 小说库支持一次选择或拖入多个小说文件；前端会按文件名自然排序，服务端把每个文件作为独立分卷边界合并到同一个知识空间，章节标题不会因跨文件重复而相互覆盖；单个文件和合并总大小均不超过 20 MB，一次最多 32 个文件
- 多卷知识空间会持久化每个原始分卷文件名；小说库卡片可以展开查看完整分卷清单，刷新或重启后仍能确认当前空间包含哪些文件
- 原作资料页的解析诊断会同步显示当前空间是单文件还是多卷合并，核对章节时可以确认当前检索范围
- 多卷解析会保留“文件边界 · 内部卷 · 章节”的层级标题；即使每个分卷都从“第 1 卷 / 第 1 章”重新编号，检索和章节导航也不会把不同文件的同名章节合并
- 小说库搜索也会检索多卷空间的每一个原始文件名，按任意分卷名称都能找回对应的统一知识空间
- 小说库搜索或状态筛选无结果时，空状态会直接提供“上传新小说”入口，用户不需要先恢复完整列表才能继续建立知识空间
- 拖拽上传也会在发送请求前校验文件格式；不支持的文件会立即提示，不会先上传后才由服务端拒绝
- 工作区导航下会持续显示当前小说名称；如果原文不可用，会直接标记“原文待恢复”，减少多小说切换时的空间误判
- 工作区导航提供当前小说快速切换，下拉选择会保留正在查看的页面；切换前仍会检查未保存的空间记忆草稿
- 模型生成或摘要提炼期间会锁定小说切换、原文上传 / 重解析和空间删除，避免异步回复落入另一部小说或项目；被拦截的下拉选择会恢复为真实当前空间
- 切换小说空间时会让旧空间的章节导航、章节阅读和原作依据请求立即失效，并关闭旧资料弹窗，避免异步结果残留到新小说页面
- 回复、剧情摘要、本幕结果和原作章节摘要在写回前都会复核请求发起时的项目 / 小说空间；即使发生异常切换，也只会放弃写入，不会污染当前空间
- 工作区导航的小说快速切换也沿用小说库的“当前空间 → 最近访问 → 空间更新时间”顺序，减少多个入口排序不一致造成的寻找成本
- 如果旧项目引用的小说空间已被移除或尚未恢复，当前空间 ID 会先校验有效性并安全回退；界面显示、原作检索、内容问答和空间记忆不会出现跨空间串线
- 服务端空间列表恢复后，如果发现本地缓存中的上传空间已经不存在，会自动标记为“原文待恢复”并清空过期解析指标；重新上传同名原文仍可复用原空间和项目绑定
- 待恢复空间卡片直接提供“恢复原文”入口；解析提醒或正文为空的空间则显示“重新解析”，两者都会保留空间 ID、项目绑定和空间记忆
- 待恢复状态会把“恢复原文”作为卡片主操作，同时保留无原文续写和查看资料入口；按钮也会带上小说名，方便多空间场景下的键盘与读屏操作
- 首次打开页面会直接落在小说库，避免先进入空的工作台；工作区导航也支持方向键、Home / End 快速切换页面
- 工作区将“小说库 / 工作台 / 原作资料 / 空间记忆 / 故事管理 / 模型与数据”分成独立页面；原作核对与长期知识维护不再挤在同一页，页面切换也会同步到 URL
- 工作区导航中的当前小说标识会同步空间就绪状态；正文为空、解析提醒或原文待恢复时会直接显示原因
- 工作台顶部会根据当前小说空间的可用性和解析质量动态给出下一步引导：原文缺失时前往小说库恢复，解析存在提醒时前往原作资料确认
- 小说库支持按小说名称、文件名或解析提示搜索，并按“可检索 / 解析提醒 / 待恢复”筛选；空间较多时仍能快速定位目标小说
- 多本小说空间会记录本机最近访问顺序；刷新服务后仍优先展示最近使用的空间，当前空间始终置顶
- 小说库会持久保存用户原始文件名；刷新或重启服务后仍显示实际上传的书名文件，不暴露内部存储文件名
- 升级前已存在的旧空间如果服务端只有内部文件名，前端同步时会优先沿用浏览器本地缓存中的可读文件名，避免历史空间升级后变得难以辨认
- 小说库筛选条件生效时会显示“清除筛选”快捷操作，搜索无结果时可以一键恢复完整空间列表
- 小说库顶部会汇总当前所有空间的健康度，直接显示可检索、解析提醒、正文为空和待恢复数量
- 小说库首次读取服务端空间时会明确显示加载状态，不会把请求尚未返回误显示成“还没有小说知识空间”
- 小说库会区分“没有空间”和“空间服务暂时不可用”；读取失败时保留本地缓存卡片，并明确提供“刷新状态”重试入口
- 原作资料页会同步当前空间的正文规模、章节单元、资料片段、编码、问答能力和解析提醒，查看依据时无需返回小说库确认状态
- 原作资料页还会显示平均片段长度与“章节上下文覆盖率”（有明确卷 / 章 / 节标题的分片占比）；遇到编码容错读取时会明确建议转为 UTF-8 后重新解析，便于判断知识空间质量
- 原作资料页可以从当前章节直接打开本机原文预览；服务端只按精确章节标题返回最多 12,000 字，不把全文写入项目或浏览器存储，方便核对解析结果后再保存空间记忆
- 章节原文阅读器支持在当前知识空间内直接切换上一章 / 下一章；边界章节会自动隐藏不可用方向，切换时仍会重新读取当前原文版本
- 章节阅读器支持“围绕本章提问”，会自动带回章节定位、切换到事实优先的内容问答并回到工作台
- 工作台回复下方的原作章节引用可以直接点击阅读；无标题长文本的“作品开篇 · 片段 N”引用会自动还原为可阅读的作品开篇标题
- 章节预览支持调用当前模型生成“原作章节摘要”草稿；摘要必须先在预览区审核，再由用户主动写入空间记忆，并以“模型整理，需以章节原文为准”单独标记
- 原作依据与章节摘要会绑定当前原文版本；重新解析或替换小说后，旧版本的来源记忆会在空间中标记为“原文已更新，请重新核对”，并自动从续写上下文隔离，避免过期依据继续参与创作
- 过期来源记忆提供“重新核对”入口，会直接打开对应章节；重新生成同一章节摘要时会更新原条目，保留置顶状态，不会重复堆积旧版本
- 小说库空间卡片会显示待重新核对的原文来源记忆数量；刷新、写入、删除或重新生成记忆后，这个空间级提醒会同步更新
- HTML、DOCX、EPUB、FB2、PDF 虽会在本机归一化为可检索文本，诊断区仍保留并显示原始解析格式，避免把文档解析误认为普通 TXT 编码读取
- 原作资料页在解析异常时提供直接修复入口：上传空间可直接选择修正版原文重新解析，其他空间可跳转小说库恢复
- 原文待恢复或正文为空时，原作资料页会同步禁用查看依据、阅读章节和内容问答入口，并把“恢复 / 重新解析”作为明确下一步；章节定位仍可先记录到工作台
- 工作区切换会在当前浏览会话内记住；刷新后会回到上一次所在页面，不会打断资料核对或连续创作
- 工作区页面会同步到 URL hash（例如 `#source`、`#story`）；多小说场景会附带空间 ID（例如 `#source/novel-…`），可以直接分享或保存某个工作区入口，浏览器前进 / 后退也会同步页面和当前小说
- 小说空间会区分“可检索、解析提醒、正文为空、待恢复”；卡片会明确显示续写与内容问答各自是否可用，避免把文件存在误认为正文已成功解析
- 发送内容问答前也会复用同一套空间就绪判断，小说库卡片显示的“内容问答可用 / 不可用”与实际发送拦截保持一致
- 对空正文或章节解析提醒的已上传小说，卡片提供“重新解析”；重新选择修正版原文后会二次确认，再保留原空间 ID、项目绑定和空间记忆
- 重新解析失败后点击“重试解析”仍会复用原目标空间，不会因为重试而生成重复小说空间；用户重新从顶部选择新文件时则会清除这个重试目标
- 上传轮询超时后点击“刷新状态”会同时恢复后台任务；任务若已完成会自动接收结果并更新小说空间，不需要重复上传
- 内容问答会在发送前检查当前知识空间是否有可检索正文；原文缺失或解析为空时会引导回小说库恢复，避免在没有原作依据时误提交事实问题；续写仍可基于已有项目设定继续
- 空间记忆独立为工作区页面：可保存人物关系、世界规则和二创约定，问答会将其作为辅助笔记而不是原作证据；页面内提供来源筛选、写入前预览和原作资料回跳
- 原作资料页支持“预览本次记忆”：发送前可查看当前续写实际会带入的空间笔记、命中原因和笔记来源；内容问答会明确显示不会使用空间记忆
- 原作资料页核对章节或依据后可以直接进入内容问答；当前章节定位会自动带回工作台，不需要手动切换模式
- 原作依据面板中的每个检索片段都支持“带回内容问答”：会自动携带当前问题、片段章节定位并切换到事实优先模式，核对依据后无需重新填写问题
- 原作依据面板中的每个检索片段都支持“阅读章节”；服务端同时返回展示标题和原始章节标题，包含无标题长文本的分片结果也能准确打开对应原文预览
- 原作检索依据支持按片段一键保存为空间记忆；保存时会保留小说名、章节和核对问题，并单独标记为“原作依据”，方便后续筛选与续写承接
- 保存原作依据时会额外记录真实章节标题、原文分片序号和原文版本；同章多分片或无标题长文本也能在空间记忆中追溯到具体来源
- 空间记忆会按更新时间选择最新的连续性笔记，置顶笔记始终优先；即使用户只输入“继续”等低信息追问，也不会因为保存顺序而误带入旧笔记
- 自动生成的剧情摘要和本幕结果会按“类型 + 标题 + 来源”更新已有记忆，不会因反复提炼不断堆叠重复版本；手动笔记仍可自由新增
- 服务端写入也会合并导入或旧客户端产生的重复自动记忆与原作依据记忆，保留原条目身份和置顶状态，确保空间记忆上限真正可控
- 空间记忆区会持续显示当前小说名称，切换知识空间后立即更新，降低多小说之间编辑错记忆的风险
- 项目下拉菜单切换到另一部小说时，会同步当前知识空间、检索策略、空间记忆和小说库高亮；笔记编辑器存在未保存内容时会先确认，避免草稿跨小说串写
- 摘要和本幕结果预览支持经过确认后写入当前小说空间记忆；写入内容仍被标记为辅助记忆，不会替代原作检索证据
- 空间记忆会标注来源类型和来源名称，并支持在当前小说空间内按关键词搜索、按手动记录 / 原作依据 / 剧情摘要 / 本幕结果筛选
- 空间记忆页会显示全部、原作资料、连续性 / 二创和待核对四类数量；点击统计卡即可快捷筛选，方便长期维护较多笔记
- 记忆搜索和来源筛选会显示当前筛选状态，并提供“清除记忆筛选”一键恢复全部笔记

- 模型服务待配置时支持一键复制当前服务缺少的环境变量键名，复制内容不包含任何配置值
- 连接测试会读取服务端请求超时配置，适配本地模型首次加载较慢的情况
- 流式生成在 90 秒无响应时会自动中止，并明确提示检查模型服务
- 服务端上游请求超时可通过 `INK_ECHO_REQUEST_TIMEOUT` 配置（默认 120 秒，自动限制在 5-600 秒）
- 服务端历史消息预算可通过 `INK_ECHO_HISTORY_BUDGET` 配置（默认 48000 字，自动限制在 8000-120000 字）
- 后端提供健康检查、模型列表、连接探测、摘要和聊天接口的 HTTP 路由回归测试
- CI 还会检查前端 HTML id、静态资源和关键控件绑定契约，减少后续迭代中的界面 wiring 回归
- 支持中途停止模型生成，并保留已经生成的内容
- 角色回复支持一键复制
- 角色回复支持保存为项目级灵感摘录，可复制或删除
- 灵感摘录可一键追加到剧情摘要，并遵守摘要字数上限
- 支持一次复制全部灵感摘录，方便粘贴到编辑器或新的创作提示中
- 最后一条角色回复支持一键重试，便于重新生成不同版本
- 重试后的角色回复会保留多个版本，可在消息下方切换并选择继续对话的版本
- 支持在当前工作区中搜索关键词，并可用同一个关键词一键继续搜索完整归档，快速定位角色、情节和旧回复
- 浏览器本地自动保存对话、作品设定和模型选择
- 本地存储不可用或空间不足时会提示先导出 JSON 备份，避免误以为内容已经保存
- 项目切换区会显示本地项目数据用量，接近浏览器存储配额时提前建议导出备份
- 作品设定、参考片段、摘要、创作要求和模型名在前端与服务端共享明确长度上限，减少误存超长内容
- 侧栏会显示当前发送上下文的大致字数，接近较重负载时用强调色提醒及时整理摘要
- 上下文用量提示会根据“完整对话 / 精简上下文”模式显示实际发送规模；完整模式的上下文预览会注明归档桥接消息
- 上下文预览会拆分显示作品设定、角色卡、对话历史和总字数，便于判断是哪一部分接近服务端预算
- 上下文预览还会同步显示项目状态与新鲜度提醒，包括摘要后新增消息和待更新的场景结果，发送前可直接核对
- 点击上下文用量可以预览并复制本次实际发送的设定和对话范围
- 上下文预览会同时列出当前角色卡、创作倾向和回复长度，方便核对模型请求前的完整创作条件
- 问答模式的上下文预览和用量统计会与实际请求一致：只显示作品 / 章节定位和原作资料助手，不把已被服务端隔离的场景计划、参考片段、摘要和创作要求计入发送上下文
- 上下文预览也会按当前模式过滤历史：问答模式隐藏带创作模式标记的历史消息，创作模式会把问答历史显示为原作参考而非剧情对话
- 上下文预览顶部会显示本次实际原作检索查询和动态检索说明；问答模式的消息计数也与过滤后的实际预览内容一致
- 历史预览会先按当前模式过滤，再按服务端同一历史预算截取，避免长对话临界处出现“预览有 / 模型没收到”或反过来的情况
- 发送前会按服务端的最近 20 条消息和历史字数预算预截取，预览内容与模型实际收到的对话范围保持一致
- 服务端普通聊天对最近对话设置 48000 字历史预算，超出时优先保留最新消息；摘要任务会在同一预算内读取本地保留的完整历史，配合剧情摘要支持更稳定的长篇创作
- 支持用当前模型一键提炼最近对话为剧情摘要，写回前会确认替换已有摘要
- 提炼剧情摘要后会先展示当前摘要与新摘要的只读对比，只有明确点击“替换摘要”才会写入，取消不会改变原摘要
- 当前未发送的文字按项目自动保存，切换项目或刷新后可恢复
- 作品设定的本地保存会合并短时间内的连续输入，长篇项目编辑时减少高频 JSON 写入；切换、导出或离开页面前仍会立即保存
- 页面刷新或关闭前会立即保存当前项目的所有表单字段，即使离开页面发生在短暂的合并保存窗口内，也不会丢失刚输入的设定
- 一键将作品设定、角色卡和对话记录导出为 Markdown
- Markdown 导出会附带当前项目的灵感摘录
- Markdown 导出前会先同步当前输入，并在有内容时附带“当前草稿”，避免未发送文字在交接时丢失
- Markdown 导出会附带检查点索引，完整检查点仍保存在项目 JSON 备份中
- Markdown 导出会保留重试生成的备选回复，方便交接、复盘和比较不同写法
- 对话超过工作区窗口后，归档消息仍会随项目复制、检查点、JSON / Markdown 导出保存，侧栏会显示已归档数量
- 对话菜单提供只读的归档历史面板，可搜索归档中的角色、情节和句子；旧消息支持复制、引用到输入框，或从归档中的角色回复创建剧情支线
- 对话菜单支持复制项目交接摘要：包含作品设定、参考片段、当前草稿、角色卡、场景计划、摘要、最近对话、摘录和检查点，可直接交给下一位 agent；参考片段和草稿各最多截取 2000 字，摘要不包含 API key 或端点
- 对话菜单也支持将项目交接摘要直接下载为 Markdown 文件，方便作为独立交接附件保存
- 归档历史面板支持在确认并完成备份后清理归档，释放本地存储空间；当前工作区消息和剧情摘要会保留
- Markdown 导出会附带场景计划和当前场景目标
- 支持在浏览器中创建、切换和删除多个创作项目
- 提供“古典余韵、原创长篇、一封未寄出的信、如果那天没有告别”四套创作模板，一键生成带设定、角色、模式和灵感卡的新项目
- 支持把当前作品的设定、角色、场景计划和灵感保存为自定义模板，最多保存 12 个；模板可删除并随全量 JSON 备份迁移
- 角色库支持跨项目保存、加入和删除角色卡，最多保存 24 个；支持按角色名、语气或人物设定即时搜索；加入同名但设定不同的角色时会确认是否覆盖当前项目卡片，角色内容会随全量 JSON 备份迁移
- 灵感库支持跨项目保存、加入和删除写作提示，最多保存 36 条；支持按名称或提示内容即时搜索，编辑项目灵感并勾选同步时会更新对应库条目，并随全量 JSON 备份迁移
- 项目较多时可按作品名称、章节、当前场景卡或角色搜索并快速切换；列表同时显示匹配数量、当前项目消息数和场景卡数
- 项目切换区会显示当前项目的谱系；复制项目、从检查点或从角色回复创建支线时，会记录来源项目及具体派生节点，并随 JSON 备份和交接摘要保存
- 检查点会保留所属小说知识空间；跨设备导入项目时，如果原空间 ID 不存在，会在确认中提示并自动重新关联当前选中的小说空间，避免导入后检索和记忆请求指向悬空空间
- 旧版本中没有空间 ID 的检查点会自动继承父项目的小说空间，升级后恢复历史检查点不会意外切回默认小说
- 项目交接摘要会显示当前小说知识空间及其可用状态，交接时可以先确认原文是否已在本机重新建立
- 项目切换区会显示当前项目状态：场景完成进度、摘要是否覆盖最新消息、待更新的场景结果和未发送草稿；项目搜索支持状态词，并提供“需要处理 / 摘要待更新 / 结果待更新 / 有草稿”一键筛选，便于在多个长篇项目间快速判断下一步
- 当搜索或状态筛选暂时隐藏当前项目时，下拉框会明确标记“当前项目未在筛选结果”，不会误显示另一个项目为当前项目
- 项目状态旁提供“去处理”入口：会优先定位到待更新摘要，其次打开场景计划处理过时结果，最后定位到未发送草稿
- 项目数量上限为 50 个，创建、复制和导入共用同一上限
- 支持复制当前项目创建平行创作支线，并保留完整上下文
- 支持从任意一条角色回复创建剧情支线，并只保留截至该处的对话、摘录、检查点和可确认的场景结果；支线会清空旧摘要、草稿和无法确认时间点的场景结果，避免后续剧情泄漏
- 支持在对话菜单中保存命名检查点，之后恢复完整创作状态
- 检查点支持直接改名，方便在长篇版本列表中补充“分岔点 / 第几幕 / 角色选择”等信息，不必删除后重建
- 检查点列表支持按名称、场景或角色搜索，并显示当前筛选结果数量
- 检查点支持与当前进度对比，查看消息数、场景、角色、摘要、草稿和场景计划的变化，并可复制对比结果
- 检查点对比还会显示摘要覆盖消息数、上下文模式、场景目标和场景结果来源变化，便于选择正确快照恢复
- 检查点支持直接创建剧情支线：从某一刻复制对话、设定、草稿和场景计划，原项目不会被改写
- 检查点列表会显示保存时的场景、目标、角色和草稿提示，便于在恢复或创建支线前辨认正确节点
- 检查点支持“快速保存”和 `⌘ / Ctrl + Shift + S` 快捷键，会按当前场景与时间自动命名，不覆盖已有检查点
- 支持将全部项目导出为 JSON 备份，并导入到另一台设备；全量导入会恢复备份时正在编辑的项目
- 小说库会明确提示交接边界：项目 JSON 不包含小说原文、章节索引和空间记忆；换设备需先重新上传原小说，再导入项目备份
- 小说库支持单独导出 / 导入空间配置包，迁移空间名称、检索策略和长期记忆；导入只写入当前已选择的小说空间，不会覆盖原文
- 空间配置包会附带原始文件名、格式和正文规模摘要；导入到同名但可能不同版本的小说时，会先提示原文不匹配风险，避免把旧版本记忆误认为当前原作设定
- 空间配置导入会校验格式和版本；遇到未来版本或损坏的长期记忆字段会拒绝导入，不会静默覆盖当前空间
- 全量项目备份当前格式为 v4；导入确认会显示备份版本，并按当前版本可识别字段兼容导入
- 全量或单项目备份会附带引用过的小说空间清单、空间名称和可用状态，但不携带小说原文、章节索引或空间记忆；导入时优先按空间 ID、再按空间名称匹配，仍找不到时才关联当前选中的空间，并在确认框中提示
- 导入备份后，小说库会保留空间恢复提示；缺失原文会列出待上传的小说名，上传成功后自动移除对应提示，空间记忆和检索策略仍可通过对应小说卡片单独导入
- 对于因缺少原文而暂时回退到当前空间的导入项目，上传同名小说后会自动恢复项目及检查点的小说空间绑定，减少跨设备交接后的手工修复；如果文件名发生变化，恢复提示会让用户先选择对应的待恢复小说空间，再按空间名称完成绑定
- 空间切换时会立即清空上一空间的记忆展示；空间记忆读取失败会显示明确状态并阻止覆盖式保存，刷新成功后才恢复编辑
- 切换小说或刷新记忆时会显示“正在读取”状态；读取完成前不会允许保存、删除或置顶，避免异步切换期间用旧空间列表覆盖新空间记忆
- 同一小说空间的连续刷新也会按请求序号丢弃旧响应；快速 A → B → A 切换时，较早返回的记忆不会覆盖最后一次读取结果
- 导入项目备份前会显示导入数量和当前项目提示，并确认后才会追加到本地项目列表
- 导入项目备份前会预览将实际导入的项目名称、消息量、场景完成进度和草稿状态，最多展开前 4 个项目，减少交接时选错备份文件的风险
- 导入或恢复明确为空的项目时会保持空白，不会自动混入演示对话
- 自定义小说项目即使缺少旧版本中的角色或对话字段，也会使用通用“主角 / 叙事助手”与当前小说开场，不会回退到《蛊真人》示例内容
- 全量备份导入会过滤无效项目条目，并在确认框和完成提示中显示跳过数量
- 备份中的有效项目超过本地 50 个项目上限时，会单独提示因容量未导入的数量
- 支持从对话菜单导出或导入单个项目 JSON，便于只交接一部作品
- 对话记录保存说话者信息，自定义角色可填写性格与语气

模型服务不可用时，页面会保留提问和本机检索依据，明确显示本次未生成；修复模型设置后可以直接重试。若已有有效回复，重试失败会保留原回复；失败提示不会成为可切换的正文版本，也不会进入后续模型上下文。

GPT-5 / o 系列等会消耗隐藏推理 token 的模型会自动获得更充足的生成预算；前端仍按精简、标准、展开控制目标篇幅，并继续依据服务端结束原因显示“已截断”，避免约 600 字的正常续写被误截成半段。

## 配置模型服务

复制 `.env.example` 为 `.env`，按需填写配置。真实密钥只放在本地环境变量中，不要提交到 GitHub。

办公网自定义服务使用以下配置：

```bash
INK_ECHO_PROVIDER=custom_azure
INK_ECHO_CUSTOM_AZURE_API_KEY=你的密钥
INK_ECHO_CUSTOM_AZURE_ENDPOINT=你的办公网端点（仅填写在本机 .env）
INK_ECHO_CUSTOM_AZURE_MODEL=gpt-5-mini-2025-08-07
INK_ECHO_CUSTOM_AZURE_LOGID=你的logid
```

如果使用 Ollama：

`INK_ECHO_OLLAMA_BASE_URL` 可以省略，默认连接本机 `http://127.0.0.1:11434/v1`。

```bash
INK_ECHO_PROVIDER=ollama
INK_ECHO_OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
INK_ECHO_OLLAMA_MODEL=qwen3:8b
```

### 原作知识库

将 `.env.example` 复制为 `.env`，配置你本机的《蛊真人》纯文本路径：

```bash
INK_ECHO_SOURCE_NAME=蛊真人
INK_ECHO_SOURCE_FILE=/绝对路径/新蛊无删减错别字修正5.0.txt
```

服务端只在本地读取并检索该文件，不提供原文静态下载，也不会把原文提交到 GitHub。
`GET /api/source/outline` 只返回去重后的卷 / 节标题，供前端章节定位建议使用，不返回正文；章节标题会写入当前知识空间的派生索引缓存，服务重启后也能直接复用，连续搜索长篇小说时不会重复整理原始分片。
`GET /api/source/chapter?title=...&novel_space_id=...` 只按当前空间的精确章节标题返回最多 12,000 字本机预览，用于解析核对；未知标题会拒绝返回，预览内容不会进入项目 JSON、空间记忆或 GitHub。

### 模型式原作记忆实验

项目已提供隔离的小样本提取 harness，但尚未接入全书生产知识库。最终实验方案不让模型自行抄写引文：服务端先把章节拆成编号原文句段，模型只选择证据编号并生成原子事实，再由服务端恢复真实原文位置，最后通过第二轮审查筛掉多事实合并、未具名实体、类别错误和时间错误。只有全部审查维度通过的条目才会晋级。

默认实验只运行三章，一次最多允许五章，结果写入 Git 忽略的 `.inkecho-data/evals/memory-extraction/`，不会覆盖现有空间记忆或规则知识索引：

```bash
python3 scripts/memory_extraction_harness.py --dry-run
python3 scripts/memory_extraction_harness.py
```

当前小样本结果和推广边界见 [`MEMORY_EXTRACTION_EVAL.md`](MEMORY_EXTRACTION_EVAL.md)。

## 本地运行

章节导航首次加载最多展示 3000 个标题；输入至少两个字符后会对完整本地章节索引进行服务端兜底检索，适合超长小说定位首批标题之外的章节。

纯前端演示可以直接双击 `index.html` 打开；要连接模型服务，请启动 Python 服务：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 server.py
```

然后访问 <http://localhost:5173>。

服务只会提供 InkEcho 的前端运行文件，不会把 `.env`、README 或测试文件作为静态资源暴露。
服务响应还会限制脚本、连接、嵌入和浏览器权限来源，保留 Google Fonts 所需的最小例外。
