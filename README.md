# InkEcho

[![CI](https://github.com/Silent-Rain02/inkecho/actions/workflows/ci.yml/badge.svg)](https://github.com/Silent-Rain02/inkecho/actions/workflows/ci.yml)

InkEcho 是一个以《蛊真人》为原作基础的续写与内容问答工作台。

接手开发可先阅读 [HANDOFF.md](HANDOFF.md)。

## 项目简介

项目围绕本地《蛊真人》知识库，提供原作内容问答、角色 / 世界观检索和非照抄式剧情续写空间。

## 当前状态

当前已完成一个可本地运行的《蛊真人》创作工作台，支持多种模型服务、流式对话、原作检索、项目管理和 JSON 备份。原始小说文件只从本机路径读取，不提交到 GitHub。

## 已实现

- 作品名称、时代氛围和世界观备注
- 当前章节 / 场景字段，帮助模型聚焦正在创作的段落
- 场景计划：每个项目最多保存 24 张场景卡，可调整顺序、记录目标、状态以及已发生的结果 / 线索并设为当前场景；同一时间只保留一个“进行中”场景，切换当前场景时会自动整理其余状态；这些信息会随受限的整体计划发送给模型
- 场景计划较长时，发送给模型的 2000 字上下文预算会优先保留当前场景、前后邻近卡片和计划首尾锚点；完整计划仍保存在本地项目中
- 场景计划支持“完成并推进”，会自动将当前场景标记为已完成、切换下一幕并同步当前章节 / 场景字段
- 当前场景没有结果，或结果已经落后于最新剧情时，点击“完成并推进”会先给出可取消的提醒，避免无意间把未整理的剧情带入下一幕
- 手动改写当前章节 / 场景时会解除原场景的“进行中”状态；编辑当前场景为“已完成 / 待写”时也会同步解除当前节点，避免计划状态与实际上下文错位
- 场景计划弹窗会显示已完成、进行中和待写数量及整体进度
- 场景计划支持按场景名称、目标或线索搜索，并按待写 / 进行中 / 已完成筛选；筛选数量与总体进度分开显示，不会隐藏当前进度信息
- 场景卡会显示结果覆盖到哪条消息；结果之后有新剧情时提示新增消息，来源不在当前支线时提醒重新提炼，避免把过时结果继续当作当前事实
- 场景计划提供“定位当前”入口，筛选后也能一键清除条件并滚动回正在写的场景卡
- 场景计划支持一键复制完整计划，包含作品、当前场景、每幕目标、状态和已记录线索，方便交接或作为新的创作上下文
- 角色回复支持一键“记为结果”，把回复追加到当前场景的结果 / 线索中，并遵守 600 字上限
- 场景计划支持用当前模型“提炼本幕”，生成不超过 600 字的场景结果，写回前会确认替换已有记录
- 提炼本幕结果会先展示当前记录与新结果的只读对比，只有明确点击“替换结果”才会写入场景卡
- 提炼摘要或本幕结果期间不能继续发送新消息；预览打开后如果对话新增或尾部发生变化，应用结果会自动作废并要求重新提炼，避免旧摘要 / 旧场景结果覆盖新剧情
- 剧情摘要和本幕结果提炼会读取本地保留的完整历史，再遵守服务端历史预算；精简上下文只影响普通聊天请求
- 混合使用问答与续写时，本幕结果提炼会排除标记为“问答”的消息；剧情摘要会把问答消息标记为原作事实参考，不会把资料查询写成角色行动或剧情事件
- 从问答切回续写、改写或独白时，历史问答会被标记为原作参考而非剧情对话，模型不会把资料回答误接成上一幕对白
- 即使较早消息已经进入归档，剧情摘要和本幕结果提炼仍会按完整历史判断是否有可用内容，不会因当前工作区变短而误报消息不足
- 每个项目工作区保留最近 120 条消息，超出的内容会归档在项目数据中（最多 360 条）；普通聊天发送最近 20 条，提炼摘要时可读取工作区与归档历史并按字数预算整理
- 作品级参考片段，可粘贴或导入 `.txt` / `.md` 文件，并随项目保存
- 剧情摘要字段，帮助模型在长对话中记住关键事件和当前悬念
- 剧情摘要会显示新鲜度：摘要之后有新消息时提示新增条数，重新提炼或手动更新后记录更新时间
- 手动编辑剧情摘要时会先显示“编辑中”，失焦或离开页面后才提交摘要覆盖范围，避免半成品摘要被误判为最新
- 支持可逆的精简上下文模式：模型只接收剧情摘要和最近两轮对话，完整历史仍保留在本地；完整上下文模式在工作区消息已归档时，会额外保留最近 4 条归档消息作为连续性桥接，避免长篇续写刚跨过归档边界就丢失上一幕线索
- 启用精简上下文前会检查摘要新鲜度；摘要后有新增消息时会显示数量并确认，避免无意中遗漏最新剧情
- 启用精简上下文前也会检查场景结果新鲜度；有未覆盖最新剧情的场景结果时会明确提示，因为场景计划仍会随请求发送
- 本次创作要求字段，可指定文风、叙事视角、禁用元素和改写边界
- 角色卡切换、自定义角色添加、编辑与删除；每张角色卡可记录性格语气之外的人物设定、愿望、秘密和关系，并随模型请求与 Markdown 导出保存
- 续写、内容问答、改写、角色独白四种创作模式，并为每种模式提供独立约束
- 内容问答是独立的《蛊真人》原作问答模式：标题显示“《蛊真人》原作问答”，回复身份显示为 InkEcho 资料助手；续写、改写和独白仍使用当前角色身份
- 问答请求会在服务端隔离当前角色卡和场景 / 参考 / 摘要等创作上下文，只保留作品与章节定位，并使用独立的原作资料助手身份、问答篇幅和事实优先提示；即使项目保存了大胆想象的创作倾向，也不会把它带入原作事实回答
- 切换到内容问答后，服务端会过滤已标记为“续写 / 改写 / 独白”的历史用户提问和角色回复，并重新按问答消息构造检索查询，避免上一轮二创内容污染原作事实回答
- 问答模式在界面上会明确显示并锁定“事实优先”；切回续写、改写或独白后恢复项目原先的创作倾向
- 模型流式生成期间会锁定模式和角色切换，避免请求按旧设定生成、界面却被切到新设定；生成结束或停止后自动恢复
- 模型流式生成期间也会锁定项目、模型服务、模型名和回复参数，避免等待期间修改的设置与当前请求串线；生成结束或停止后自动恢复
- 本地原作知识库：按卷 / 节切分文本，使用《蛊真人》领域词、二字词覆盖、标题命中和轻量稀有度评分检索相关片段；涉及方源初次重生回到青茅山的问题会优先定位开篇篇章，续写和问答共享检索上下文
- 检索结果会按当前原文版本做短期缓存；同一轮问答构造提示和返回依据时不会重复扫描全部片段，原文文件变化后缓存自动失效
- 当用户填写当前章节 / 场景时，检索会把明确的“第 X 节 / 章 / 卷”作为强定位信号，续写时优先返回对应篇章，避免被后文重复出现的人物或蛊虫名称带偏
- 章节定位会统一处理中式和阿拉伯数字，例如“第十九节”和“第19节”会命中同一原作篇章
- 当章节号和明确的蛊虫 / 人物 / 势力同时出现在查询中时，检索会优先保留“章节 + 实体”共同命中的篇章，降低多卷同序号章节的噪声
- 左侧“当前章节 / 场景”输入框会从本机知识库加载安全的卷 / 节标题建议，可直接输入关键词选择原作定位；建议列表只包含标题，不会把原文上传或写入前端项目数据
- 续写命中明确章节时，会在当前篇章之外补入紧邻的下一篇章作为“原作接续桥”；内容问答仍只使用直接命中的证据，避免把后文内容混入事实回答
- 关系型问答会优先选择同时提到多个关键人物、势力或蛊虫的原文片段，减少把两个单独命中拼成关系结论的情况
- 关系型问答也会识别“方源”“方正”等两字人物名；问答检索不会把当前二创场景目标当作原作证据查询词，避免续写意图污染事实回答
- 续写或问答只输入“继续写下去”“为什么”等低信息追问时，检索会自动回溯上一条有内容的问题，并合并当前章节与场景目标，避免原作依据突然断开
- 内容问答会在回复下方显示检索到的原作章节标题，便于回看依据；界面不会把原文全文作为静态资源公开
- 回复还会显示检索命中质量：命中充分、命中有限、单一命中或未命中；这是原文检索强度提示，不代表模型答案的事实置信度
- 重试生成的多版本回复会分别保存原作章节、依据查询和检索强度；切换版本时“查看依据”会跟随当前版本，不会沿用另一版回复的来源
- 问答系统提示会根据检索强度动态收紧事实边界：命中有限或未命中时，模型必须把无法直接由片段支持的内容标为推断或不确定
- 问答事实句会被要求尽量标注“依据：章节标题”，并明确禁止用模型记忆把多个片段拼成未被当前片段直接支持的结论；“查看依据”面板同时显示检索强度，并提醒检索强度不等于答案事实置信度
- 服务端会把问答中的章节引用与本次实际检索章节做一次轻量核对；引用不在检索结果内时，回复会显示“引用待核对”徽标，并列出待核对章节，不会静默把模型自报的章节当成已验证依据
- 引用核对只提取“第 X 卷 / 章 / 节”等章节标记，不会把“原作依据”后的解释性句子误判成章节；中式和阿拉伯数字引用也会统一比对
- 引用与本次检索结果相符时，回复会显示“引用已核对”徽标；切换重试版本时，已核对 / 待核对状态会随当前版本同步
- 复制对话、Markdown 导出和项目交接摘要也会保留“引用核验：已核对”或待核对提示，交接时不会丢失证据状态
- 重试产生多个回复版本时，引用核验状态会与每个版本分别保存；切换版本、复制对话或导出 Markdown / 交接摘要时不会沿用另一版的核验结果
- 模型达到当前篇幅上限时，服务端会返回 `truncated` 标记；前端显示“已截断”徽标并提示切换“展开”后重试，不会把半截回复伪装成完整答案
- “已截断”的最后一条回复会直接提供“展开重试”按钮；这次重试只使用展开篇幅，不修改项目默认回复长度，并继续保留为新的回复版本
- 每条消息会保存生成时的模式；切换到另一种模式后重试旧回复仍沿用原模式，消息徽标、复制对话、Markdown 导出和项目交接都会保留这个标记
- 切换到“内容问答”后，右侧灵感卡会自动变成人物处境、蛊虫辨析和势力关系等快捷问题，一键填入提问框
- 点击“查看依据”可以在本地临时面板中展开有限检索片段，支持复制核对；这些片段不会写入项目历史
- 发送前可点击输入框旁的“先检索原作依据”，先查看当前问题命中的章节和证据窗口，再决定是否交给模型回答
- “先检索原作依据”和回复下方的“查看依据”会沿用正式请求的模式边界：问答不带入二创历史 / 场景目标，续写才会追加当前场景与相邻章节接续桥
- 原作依据会围绕实际命中词截取有限证据窗口，避免命中词在长片段后半段时只展示无关的片段开头
- 每条模型回复会保存当次实际检索查询，因此即使之后修改当前章节或场景，回看依据仍能复现原请求
- `/api/chat` 和流式 `start` 事件会回传服务端最终采用的 `source_query`；前端会用它覆盖本地临时查询，保证依据面板、导出和项目交接使用同一份来源记录
- Markdown 导出和项目交接摘要会保留问答回复的安全章节标题与依据查询，方便下一位 agent 复核；不会把原文全文写入导出文件
- 复制当前对话时也会保留同样的问答依据标注，粘贴到编辑器或交接消息中不会丢失来源
- 模型服务暂时不可用时，内容问答不会伪造结论；回复会保留“查看依据”入口，仍可使用本机检索结果核对问题
- 若模型服务失败，回复会标记为演示 / 降级状态，不会把检索片段直接写成模型答案
- 从旧版本升级时，内置的“红楼梦 / 林黛玉 / 贾宝玉”演示项目会触发一次迁移，默认切换到《蛊真人》；其他用户项目会原样保留
- 项目级创作倾向：克制叙事、平衡、大胆想象
- 项目级回复长度：精简、标准、展开，并作用于流式生成预算
- 对话消息发送、快捷键发送和会话重置
- 支持一键进入专注模式，隐藏两侧配置面板并放大对话区，选择会在本机记忆
- 提供命令面板：按 `⌘ / Ctrl + K` 搜索并执行新建项目、快速保存检查点、打开场景计划、查看归档、预览上下文、连接诊断和导出等操作
- 专注模式下仍会在对话标题显示当前场景，避免长篇创作时失去叙事位置
- 最后一轮用户提问支持编辑后重新发送
- 会话工具菜单支持复制当前对话、导出和重新开始
- 重新开始前会确认将要清空的内容，同时保留作品设定、摘录和检查点
- 重新开始会同时清空当前工作区、归档历史、剧情摘要和草稿，避免旧剧情继续进入新会话；角色、场景计划、摘录和检查点会保留
- 创作灵感卡片，可一键填入写作提示
- 支持按项目保存自定义灵感卡片，可一键使用、编辑或删除
- 模型服务切换：办公网自定义 Azure、Ollama、OpenAI、Azure OpenAI、OpenAI-compatible
- 每个项目会分别记住不同模型服务的模型名，切换办公网 Azure、Ollama 或兼容接口时不会互相覆盖
- 模型状态会区分“配置完整”和“已连接”：Ollama、OpenAI-compatible 会通过模型列表请求验证连通性；办公网 Azure 会明确标记为配置完成，因为企业端点通常不提供模型列表接口
- 服务端会识别 `.env.example` 中的占位符，不会把未替换的密钥、端点或部署名误报为配置完整
- 办公网 `X-TT-LOGID` 支持 `${your_logid}` 这类示例占位符；未替换时不会把占位符请求头发给模型网关
- 健康检查会在不返回敏感值的前提下提示缺少的配置项；模型服务设置区还会直接显示需要补充的环境变量键名，例如模型名、办公网端点或 API 密钥对应的变量
- 本地缺少模型或环境变量时，聊天、连接测试和模型列表接口都会直接返回 400 配置提示；常见的认证失败、权限不足、模型不存在、限流、超时和网络错误会转换为不泄露敏感信息的中文诊断，并返回对应 HTTP 状态码（找不到模型 / 部署为 404）
- 支持从 Ollama、OpenAI 和 OpenAI-compatible 服务读取可用模型列表
- 切换到 Ollama、OpenAI 或 OpenAI-compatible 时会自动刷新模型列表；办公网 Azure 保留手动模型名，因为企业端点通常不提供列表接口
- 兼容部分 OpenAI-compatible 服务返回的结构化文本片段，普通回复、流式回复和摘要都会统一拼接文本内容
- Ollama 本地模型支持，可配置 `qwen3:8b` 等模型
- 模型流式输出，回复会逐字出现在对话框中
- 角色回复支持安全渲染常见 Markdown 标题、粗体、斜体、列表、引用和行内代码，同时复制仍保留原始文本
- 模型回复保留原有换行，连接状态会区分配置、连接成功、连接失败和离线演示
- 模型服务不可用时生成的本地演示回复会在消息旁明确标记“演示回复”，并在 Markdown 导出和项目交接摘要中保留提示，避免把演示内容误当成真实模型输出
- 健康检查和模型列表读取带有超时保护，切换服务时不会被旧请求覆盖状态
- 支持手动“测试连接”，用一次最小模型请求验证当前服务的密钥、端点和模型部署
- 办公网探测请求保留极小但可完成隐藏推理的输出预算，避免企业网关将 `max_tokens` 过小误判为连接失败
- 支持打开“连接诊断”面板，集中查看各模型服务配置状态、缺少字段、缺少的环境变量键名、当前模型、请求超时和历史预算；诊断内容不包含密钥或端点值
- 模型服务待配置时支持一键复制当前服务缺少的环境变量键名，复制内容不包含任何配置值
- 连接测试会读取服务端请求超时配置，适配本地模型首次加载较慢的情况
- 流式生成在 90 秒无响应时会自动中止，并明确提示检查模型服务
- 服务端上游请求超时可通过 `INK_ECHO_REQUEST_TIMEOUT` 配置（默认 120 秒，自动限制在 5-600 秒）
- 服务端历史消息预算可通过 `INK_ECHO_HISTORY_BUDGET` 配置（默认 48000 字，自动限制在 8000-120000 字）
- 后端提供健康检查、模型列表、连接探测、摘要和聊天接口的 HTTP 路由回归测试
- CI 还会检查前端 HTML id、静态资源和关键控件绑定契约，减少后续迭代中的界面 wiring 回归
- 支持中途停止模型生成，并保留已经生成的内容
- 角色回复支持一键复制
- 角色回复支持保存为项目级灵感摘录，可复制或删除
- 灵感摘录可一键追加到剧情摘要，并遵守摘要字数上限
- 支持一次复制全部灵感摘录，方便粘贴到编辑器或新的创作提示中
- 最后一条角色回复支持一键重试，便于重新生成不同版本
- 重试后的角色回复会保留多个版本，可在消息下方切换并选择继续对话的版本
- 支持在当前工作区中搜索关键词，并可用同一个关键词一键继续搜索完整归档，快速定位角色、情节和旧回复
- 浏览器本地自动保存对话、作品设定和模型选择
- 本地存储不可用或空间不足时会提示先导出 JSON 备份，避免误以为内容已经保存
- 项目切换区会显示本地项目数据用量，接近浏览器存储配额时提前建议导出备份
- 作品设定、参考片段、摘要、创作要求和模型名在前端与服务端共享明确长度上限，减少误存超长内容
- 侧栏会显示当前发送上下文的大致字数，接近较重负载时用强调色提醒及时整理摘要
- 上下文用量提示会根据“完整对话 / 精简上下文”模式显示实际发送规模；完整模式的上下文预览会注明归档桥接消息
- 上下文预览会拆分显示作品设定、角色卡、对话历史和总字数，便于判断是哪一部分接近服务端预算
- 上下文预览还会同步显示项目状态与新鲜度提醒，包括摘要后新增消息和待更新的场景结果，发送前可直接核对
- 点击上下文用量可以预览并复制本次实际发送的设定和对话范围
- 上下文预览会同时列出当前角色卡、创作倾向和回复长度，方便核对模型请求前的完整创作条件
- 问答模式的上下文预览和用量统计会与实际请求一致：只显示作品 / 章节定位和原作资料助手，不把已被服务端隔离的场景计划、参考片段、摘要和创作要求计入发送上下文
- 上下文预览也会按当前模式过滤历史：问答模式隐藏带创作模式标记的历史消息，创作模式会把问答历史显示为原作参考而非剧情对话
- 历史预览会先按当前模式过滤，再按服务端同一历史预算截取，避免长对话临界处出现“预览有 / 模型没收到”或反过来的情况
- 发送前会按服务端的最近 20 条消息和历史字数预算预截取，预览内容与模型实际收到的对话范围保持一致
- 服务端普通聊天对最近对话设置 48000 字历史预算，超出时优先保留最新消息；摘要任务会在同一预算内读取本地保留的完整历史，配合剧情摘要支持更稳定的长篇创作
- 支持用当前模型一键提炼最近对话为剧情摘要，写回前会确认替换已有摘要
- 提炼剧情摘要后会先展示当前摘要与新摘要的只读对比，只有明确点击“替换摘要”才会写入，取消不会改变原摘要
- 当前未发送的文字按项目自动保存，切换项目或刷新后可恢复
- 作品设定的本地保存会合并短时间内的连续输入，长篇项目编辑时减少高频 JSON 写入；切换、导出或离开页面前仍会立即保存
- 页面刷新或关闭前会立即保存当前项目的所有表单字段，即使离开页面发生在短暂的合并保存窗口内，也不会丢失刚输入的设定
- 一键将作品设定、角色卡和对话记录导出为 Markdown
- Markdown 导出会附带当前项目的灵感摘录
- Markdown 导出前会先同步当前输入，并在有内容时附带“当前草稿”，避免未发送文字在交接时丢失
- Markdown 导出会附带检查点索引，完整检查点仍保存在项目 JSON 备份中
- Markdown 导出会保留重试生成的备选回复，方便交接、复盘和比较不同写法
- 对话超过工作区窗口后，归档消息仍会随项目复制、检查点、JSON / Markdown 导出保存，侧栏会显示已归档数量
- 对话菜单提供只读的归档历史面板，可搜索归档中的角色、情节和句子；旧消息支持复制、引用到输入框，或从归档中的角色回复创建剧情支线
- 对话菜单支持复制项目交接摘要：包含作品设定、参考片段、当前草稿、角色卡、场景计划、摘要、最近对话、摘录和检查点，可直接交给下一位 agent；参考片段和草稿各最多截取 2000 字，摘要不包含 API key 或端点
- 对话菜单也支持将项目交接摘要直接下载为 Markdown 文件，方便作为独立交接附件保存
- 归档历史面板支持在确认并完成备份后清理归档，释放本地存储空间；当前工作区消息和剧情摘要会保留
- Markdown 导出会附带场景计划和当前场景目标
- 支持在浏览器中创建、切换和删除多个创作项目
- 提供“古典余韵、原创长篇、一封未寄出的信、如果那天没有告别”四套创作模板，一键生成带设定、角色、模式和灵感卡的新项目
- 支持把当前作品的设定、角色、场景计划和灵感保存为自定义模板，最多保存 12 个；模板可删除并随全量 JSON 备份迁移
- 角色库支持跨项目保存、加入和删除角色卡，最多保存 24 个；支持按角色名、语气或人物设定即时搜索；加入同名但设定不同的角色时会确认是否覆盖当前项目卡片，角色内容会随全量 JSON 备份迁移
- 灵感库支持跨项目保存、加入和删除写作提示，最多保存 36 条；支持按名称或提示内容即时搜索，编辑项目灵感并勾选同步时会更新对应库条目，并随全量 JSON 备份迁移
- 项目较多时可按作品名称、章节、当前场景卡或角色搜索并快速切换；列表同时显示匹配数量、当前项目消息数和场景卡数
- 项目切换区会显示当前项目的谱系；复制项目、从检查点或从角色回复创建支线时，会记录来源项目及具体派生节点，并随 JSON 备份和交接摘要保存
- 项目切换区会显示当前项目状态：场景完成进度、摘要是否覆盖最新消息、待更新的场景结果和未发送草稿；项目搜索支持状态词，并提供“需要处理 / 摘要待更新 / 结果待更新 / 有草稿”一键筛选，便于在多个长篇项目间快速判断下一步
- 当搜索或状态筛选暂时隐藏当前项目时，下拉框会明确标记“当前项目未在筛选结果”，不会误显示另一个项目为当前项目
- 项目状态旁提供“去处理”入口：会优先定位到待更新摘要，其次打开场景计划处理过时结果，最后定位到未发送草稿
- 项目数量上限为 50 个，创建、复制和导入共用同一上限
- 支持复制当前项目创建平行创作支线，并保留完整上下文
- 支持从任意一条角色回复创建剧情支线，并只保留截至该处的对话、摘录、检查点和可确认的场景结果；支线会清空旧摘要、草稿和无法确认时间点的场景结果，避免后续剧情泄漏
- 支持在对话菜单中保存命名检查点，之后恢复完整创作状态
- 检查点支持直接改名，方便在长篇版本列表中补充“分岔点 / 第几幕 / 角色选择”等信息，不必删除后重建
- 检查点列表支持按名称、场景或角色搜索，并显示当前筛选结果数量
- 检查点支持与当前进度对比，查看消息数、场景、角色、摘要、草稿和场景计划的变化，并可复制对比结果
- 检查点对比还会显示摘要覆盖消息数、上下文模式、场景目标和场景结果来源变化，便于选择正确快照恢复
- 检查点支持直接创建剧情支线：从某一刻复制对话、设定、草稿和场景计划，原项目不会被改写
- 检查点列表会显示保存时的场景、目标、角色和草稿提示，便于在恢复或创建支线前辨认正确节点
- 检查点支持“快速保存”和 `⌘ / Ctrl + Shift + S` 快捷键，会按当前场景与时间自动命名，不覆盖已有检查点
- 支持将全部项目导出为 JSON 备份，并导入到另一台设备；全量导入会恢复备份时正在编辑的项目
- 全量项目备份当前格式为 v4；导入确认会显示备份版本，并按当前版本可识别字段兼容导入
- 导入项目备份前会显示导入数量和当前项目提示，并确认后才会追加到本地项目列表
- 导入项目备份前会预览将实际导入的项目名称、消息量、场景完成进度和草稿状态，最多展开前 4 个项目，减少交接时选错备份文件的风险
- 导入或恢复明确为空的项目时会保持空白，不会自动混入演示对话
- 全量备份导入会过滤无效项目条目，并在确认框和完成提示中显示跳过数量
- 备份中的有效项目超过本地 50 个项目上限时，会单独提示因容量未导入的数量
- 支持从对话菜单导出或导入单个项目 JSON，便于只交接一部作品
- 对话记录保存说话者信息，自定义角色可填写性格与语气

模型服务不可用时，页面会自动回退到演示回复。

## 配置模型服务

复制 `.env.example` 为 `.env`，按需填写配置。真实密钥只放在本地环境变量中，不要提交到 GitHub。

办公网自定义服务使用以下配置：

```bash
INK_ECHO_PROVIDER=custom_azure
INK_ECHO_CUSTOM_AZURE_API_KEY=你的密钥
INK_ECHO_CUSTOM_AZURE_ENDPOINT=你的办公网端点（仅填写在本机 .env）
INK_ECHO_CUSTOM_AZURE_MODEL=gpt-5-mini-2025-08-07
INK_ECHO_CUSTOM_AZURE_LOGID=你的logid
```

如果使用 Ollama：

`INK_ECHO_OLLAMA_BASE_URL` 可以省略，默认连接本机 `http://127.0.0.1:11434/v1`。

```bash
INK_ECHO_PROVIDER=ollama
INK_ECHO_OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
INK_ECHO_OLLAMA_MODEL=qwen3:8b
```

### 原作知识库

将 `.env.example` 复制为 `.env`，配置你本机的《蛊真人》纯文本路径：

```bash
INK_ECHO_SOURCE_NAME=蛊真人
INK_ECHO_SOURCE_FILE=/绝对路径/新蛊无删减错别字修正5.0.txt
```

服务端只在本地读取并检索该文件，不提供原文静态下载，也不会把原文提交到 GitHub。
`GET /api/source/outline` 只返回去重后的卷 / 节标题，供前端章节定位建议使用，不返回正文。

## 本地运行

纯前端演示可以直接双击 `index.html` 打开；要连接模型服务，请启动 Python 服务：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 server.py
```

然后访问 <http://localhost:5173>。

服务只会提供 InkEcho 的前端运行文件，不会把 `.env`、README 或测试文件作为静态资源暴露。
服务响应还会限制脚本、连接、嵌入和浏览器权限来源，保留 Google Fonts 所需的最小例外。
