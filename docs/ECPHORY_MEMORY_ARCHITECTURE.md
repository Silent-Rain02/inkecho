# InkEcho 原作记忆架构

## 决策

记忆算法直接在 InkEcho 仓库内实现，不加载外部仓库，也不依赖独立记忆服务。

核心思路是：将审查通过的原作事实组织成实体记忆痕迹和关联图，再结合关键词、实体、可选语义分数与章节时序进行召回。所有结果最终回到逐字原文证据，结构化记忆不能替代小说原文。

## 第一性原理

```text
原文章节
  → 模型抽取候选事实
  → 本地证据校验
  → 独立模型审查
  → 已核准事实 claim
  → 实体记忆痕迹 / 共现图 / 词项索引

用户问题或续写目标
  → 提取实体与主题线索
  → 直接实体命中
  → 最多两跳关联扩展
  → 关键词 + 实体 + 语义 + 显著性融合排序
  → 按当前章节过滤未来事实
  → 返回 claim、关联路径和逐字证据
```

## 数据模型

### Claim（已核准事实）

每条 claim 必须保留：

- 小说空间、原文版本和章节位置
- `subject / predicate / object / statement`
- `category / certainty / time_scope / salience`
- 逐字证据及其原文位置
- 抽取和审查状态

同一原文版本下的 claim 集合会生成不可变的 `memory_revision`。重新抽取会创建新版本，不覆盖旧结果。

### Engram（实体记忆痕迹）

每个明确实体建立一个记忆痕迹，保存：

- 规范实体名与别名
- 关联 claim ID
- 共现实体及权重
- 出现章节和时间范围

实体之间的边来自同一条已核准事实中的共现，不额外生成脱离证据的关系摘要。

## 召回算法

默认关联深度为两跳，并融合四类信号：

1. 词项匹配：对事实、主客体和章节标题计算稀有度加权分数。
2. 实体命中：问题中直接出现实体时优先激活对应记忆痕迹。
3. 关联扩展：沿共现图逐跳扩展并衰减，解决“某人的盟友拥有什么”一类多跳问题。
4. 可选语义分数：通过注入式 scorer 接入本地或远端 embedding，不让核心算法绑定模型供应商。

续写还会传入章节截止位置，任何发生在截止点之后的 claim 都不会进入当前状态上下文。

## 记忆生命周期与二次规范化

抽取和审查通过不等于一条记忆适合直接回答。写入不可变 revision 前，会执行一层不依赖模型的确定性规范化：

- `canonical_fact`：稳定设定、关系和可复用人物事实。
- `state_snapshot`：带章节或时间范围的身份、境界、持有状态等。
- `event`：剧情事件，默认保留时间和章节边界。
- `answerability`：`self_contained`、`context_required`、`retrieval_only`，分别表示可独立回答、需要回看上下文、只用于定位原文。
- `lifecycle_status`：`active`、`duplicate`、`disputed`、`deprecated`、`superseded`。旧证据不删除，重复项和已更新项在召回时降级或过滤。

稳定事实按规范化的 `category / subject / predicate / object` 建立记忆簇；同簇的重复证据保留在 revision 中，并通过 `duplicate_of` 指向代表条目。对不同章节中的单值状态先标记为 `temporal_state_variant`，不自动选择新旧版本，避免把小说中的时间变化误判成错误；真正的矛盾才进入 `disputed`。后续可以在同一模型上增加人工或模型确认的 `supersedes` 操作，而不需要重提取原文。

这层设计参考 Mem0 的“写入前关联记忆、去重/更新、检索时融合实体与关键词”的思路，但保留 InkEcho 的原文优先约束：规范化只改变检索权重和生命周期，不覆盖逐字证据，也不把模型摘要当成原作事实。

## 持久化与上线边界

- 每个小说空间完全隔离。
- 每个原文版本和记忆版本都不可变保存。
- 新构建的索引默认是 `pilot`，不会影响产品问答。
- pilot 在推广前可以执行整库第二次独立审计；审计发现的可修复问题只能复用原证据，并在修复后再次独立复核。
- 构建器会用当前确定性规则重新校验历史报告，避免旧规则放行的事实进入新版本。
- 人工与自动评测通过后，必须带准确的 `memory_revision` 才能提升为 `production`。
- 产品只读取与当前原文 revision 完全一致的 production 索引；否则自动回退到原文检索。

## 任意小说后台构建

- 上传解析完成后，原文检索和问答立即可用；深度记忆不会自动产生模型费用。
- 用户显式启动后，系统从全书首尾和中间位置均匀选取 6 个代表章节，硬上限为 12 章。
- 每完成一章就写入本地检查点；应用中断、网络错误或用户暂停后可以续建。
- 质量门禁失败会进入 `needs_review`，不会构建或启用索引；再次构建会丢弃失败结果并重新抽取，而不是伪续跑。
- 通过门禁后只生成 `pilot_ready` 不可变版本；前端必须携带准确 `memory_revision` 显式启用，才能成为 `production`。
- 原文 revision 在构建中或构建后发生变化时，任务和旧 production 均视为失效，产品继续使用全文检索。
- 后台状态只保存任务阶段、进度与版本，不持久化 API key、端点或原文章节内容；原文证据保存在本地记忆版本中。

## 评测门槛

全书构建前，在小规模章节上至少检查：

- 单事实和人物关系召回
- 两跳关系问题
- 世界规则与时间线问题
- 传闻、角色认知和客观事实的区分
- 未来信息泄漏
- 每条结果能否回到准确章节与逐字证据

证据准确率是硬门槛；召回数量和覆盖率不能以牺牲事实可靠性为代价。
